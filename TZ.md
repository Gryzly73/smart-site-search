# ТЗ. Поиск по каталогу store.softline.ru

Рабочее ТЗ по кик-оффу «Умный поиск на сайте» (26.11.2026) и разбору выданных файлов. Числа ниже посчитаны по `docs/Mindbox.yml.gz.xml`, дата фида `2026-11-25 14:12`.

## 1. Цель

Поисковый запрос разбирается в потребность и возвращает карточки товаров. Совпадение идёт по смыслу запроса, а не по тексту описания. В ответе не меньше четырёх карточек: точные попадания и соседние товары для допродажи.

В постановке: около 500 обращений к поиску в день, товарная матрица около 200 000 наименований. В выданном фиде 136 040 офферов. Готовое размещение на витрине не требуется. Готовых интеграций с API нет.

## 2. Термины

| Термин | Что это в фиде |
|---|---|
| Класс | Наша товарная группа: «операционная система», «информационная безопасность». В фиде такого поля нет |
| Карточка | Товар, который ищет человек |
| Оффер | Одна лицензия или одна позиция оборудования: цена, наличие, характеристики |
| Полка | Категория 2-го уровня. Её `id` стоит в `categoryId` оффера. Это не карточка и не класс |
| Характеристика | `param` оффера. На карточке хранится перечень встреченных значений |

Карточка софта и карточка электроники устроены по-разному. Это разобрано в разделе 5. `categoryId` для поиска карточки не используется.

## 3. Источники данных

Архив `docs/drive-download-20261126T072824Z-1-001.zip` (6,9 МБ) содержит три файла. Рядом лежат те же файлы в распакованном виде. Калькулятор экономики к каталогу не относится и в поиск не входит.

### 3.1. Каталог YML

`docs/Mindbox.yml.gz.xml`, 292 МБ, около 4,05 млн строк. В имени есть `.gz`, внутри обычный XML UTF-8, формат YML Яндекс Маркета (`shops.dtd`). Магазин `store.softline.ru`.

В `shop` только три блока: `currencies`, `categories`, `offers`.

```text
yml_catalog
└─ shop
   ├─ name, company, url
   ├─ currencies
   │  └─ currency                 одна валюта, RUR
   ├─ categories                   9 311
   │  └─ category                  id, необязательный parentId, текст — имя
   └─ offers                       136 040
      └─ offer                     id, available; у софта ещё group_id
         ├─ name, vendor, vendorUrl, vendorCode, url
         ├─ price, currencyId, categoryId, picture
         ├─ delivery, pickup, description
         ├─ oldprice, sales_notes, group_id     не у всех
         └─ param                               name + значение, имя может повториться
```

Категории, глубина не больше 3:

| Уровень | Сколько | Роль | Пример |
|---|---:|---|---|
| 1, без `parentId` | 54 | отдел | Операционные системы |
| 2 | 497 | полка, на неё ссылается `categoryId` | Российские операционные системы |
| 3 | 8 760 | имя карточки софта, если на `id` есть офферы | Astra Linux Special Edition |

Офферы ссылаются только на полки 2-го уровня: у всех 136 040 `categoryId` — категория глубины 2. Семь отделов пустые, поэтому занятых полок чуть меньше 497.

Офферы:

| | |
|---|---|
| Всего | 136 040 |
| `available="true"` | 44 601 |
| `available="false"` | 91 439 |
| Цена `0` | 80 269, все с `available="false"` |
| С `group_id` | 127 915, все с типом продукта «софт» |
| Без `group_id` | 8 125, все с типом продукта «электроника» |
| Вендоры | 1 232 |
| `param` | около 1,9 млн, в среднем 14 на оффер |
| `oldprice` | 80 301 |
| `sales_notes` | 28 096, порог партии |
| `vendorCode` пустой | 91 062 |

У каждого оффера есть `name`, `vendor`, `vendorUrl`, `vendorCode`, `url`, `price`, `currencyId`, `categoryId`, `picture` (одна картинка 168×168), `delivery`, `pickup`, `description`. `vendorCode` часто пустой. `description` иногда пустой. Имя обрезано на 119 символах: 7 786 названий упираются в потолок.

`description` у большинства офферов — склейка характеристик («Язык интерфейса: … • Срок действия: …»), медиана 92 символа. Связный текст длиннее 400 символов есть у 368 карточек. Текстом карточки это поле не считается.

Значение `param` «другое или отсутствует» и «не определено» — пустая характеристика. Так закрыты почти у всего софта версия, платформа, номер в реестре отечественного ПО, сертификаты, модель лицензирования и состав пакета.

Пример софта. Карточка — категория `121231` «Astra Linux Special Edition», полка `222320` «Российские операционные системы». 803 оффера с `group_id="121231"`, все доступны, цены от 294 до 4 181 600 ₽. Адрес карточки на витрине `https://store.softline.ru/astralinux/astra-linux-special-edition/` в фиде отсутствует. В фиде есть адрес вендора `vendorUrl` и адрес конкретной лицензии в `url`.

### 3.3. Постановка и витрина

`docs/ИИкузница_—_Умный поиск на сайте.pdf`, 254 КБ, пять страниц. Оттуда берутся требования к ответу: смысл запроса, жаргон и опечатки, различие «серверное оборудование» и «ПО для сервера», не меньше четырёх товаров, соседние товары. Примеры словаря из постановки: «антивирь», «офис», «винда», «астра линукс», «мдаемон».

Сайт `store.softline.ru` и сайты вендоров в репозитории не выгружены. Их можно использовать, чтобы подтвердить синоним или добрать текст, которого нет в `param`. На приёмку каталожного поиска это не влияет.

## 4. Что считать карточкой

Один тег `category` означает три разные вещи. Карточкой является только часть из них.

Отдел — категория без родителя. Полка — категория, чей родитель является отделом; её id попадает в `categoryId`. Карточка софта — категория третьего уровня, чей id совпал с `group_id` офферов. Таких карточек 4 413. Остальные категории третьего уровня пустые и в индекс не входят.

Связь однозначная. У оффера не больше одного `group_id`. Офферы карточки — все `offer` с этим `group_id`. Поиск по `categoryId` возвращает всю полку: у Astra на полке `222320` вместе с ней лежат РЕД ОС, Альт и РОСА.

## 5. Софт и электроника

Деление уже есть в данных и совпадает с `param` «Тип продукта». От него зависят и карточка, и ход поиска.

| | Софт | Электроника |
|---|---|---|
| Офферов | 127 915 | 8 125 |
| Карточек | 4 413 | 8 125 |
| Как собрана карточка | `group_id` = id категории 3-го уровня | сам оффер, `group_id` нет |
| Идентификатор карточки | `group:<id>` | `offer:<id>` |
| Что внутри карточки | несколько лицензий: медиана 7, у 90% групп не больше 65, максимум 2 952 | одна позиция |
| Полка | класс назначается по полке, но полка шире карточки | полка близка к классу: «Ноутбуки», «Десктопы» |
| Характеристики | матрица лицензии: поставка, пользователь, срок, редакция | свойства устройства: форм-фактор, сокет, процессор, цвет; заполнены не у всех |
| Имя | вендор, продукт и условия лицензии, обрезка на 119 символах | имя конкретной позиции |

Софт ищется в два шага. Сначала карточка: по имени, вендору и классу, без чтения всех лицензий. Потом, если в запросе есть характеристики лицензии, офферы только этой карточки. Запрос «астра линукс» обязан вернуть `group:121231`, а не 803 строк лицензий и не всю полку российских ОС. Редакция, срок и поставка уточняют лицензию внутри уже найденной карточки.

Электроника ищется в один шаг. Карточка и оффер — одна запись, второй выборки лицензий нет. Фильтры запроса сразу ограничивают эти записи: форм-фактор, тип устройства и другие заполненные `param`. Класс берётся с полки: «Ноутбуки» и «Десктопы» входят в «компьютеры и ноутбуки», «Серверы и опции» — в «серверы».

Общий запрос идёт по обеим веткам, когда класс неоднозначен. «Сервер» возвращает карточки класса «серверы» и программные карточки, у которых среди офферов назначение — сервер. Полка «Серверное ПО» в отделе «Сеть и интернет» в этот ответ целиком не попадает: в ней смешаны разные программы. «Сетевое оборудование» — электроника, «Сеть и интернет» — софт; это разные классы, несмотря на близкие слова.

## 6. Классификация карточек

Дерево магазина классом не считается. Внутри одного отдела полки нарезаны по разным признакам: функция, аудитория, платформа, происхождение, иногда один продукт, иногда остаток «Другие программы». Одни и те же товары продублированы в отделе SaaS. «Антивирусы для организаций», «Антивирусы для Windows», «Российские антивирусы» и антивирусный SaaS — один класс, а аудитория, платформа и отечественное происхождение — флаги.

Класс назначается карточке при загрузке, один на карточку. Windows 11, Linux и Astra Linux получают класс «операционная система», хотя в фиде у них четыре разные полки.

Классы софта: операционная система; информационная безопасность; офисное ПО; работа с текстом; CRM, ERP и учёт; разработка и базы данных; САПР и ГИС; графика и дизайн; виртуализация; резервное копирование; системные утилиты; удалённый доступ; коммуникации; обучение.

Классы оборудования: серверы; компьютеры и ноутбуки; комплектующие; периферия; сетевое оборудование; офисная техника; телефоны и гарнитуры.

Полки «Серверное ПО», «Другие программы», «Другое офисное ПО» класс не задают. Для карточек на таких полках класс определяется по имени карточки и вендору. Сертификат техподдержки — значение «тип лицензии», не класс и не отдельная карточка.

Флаги карточки: отечественное (полка содержит «Российские» или «Импортозамещение») и SaaS (отдел «Облачные решения (SaaS)»).

Соседи для добора задаются словарём классов. Для «операционной системы» соседи — информационная безопасность, офисное ПО, виртуализация.

## 7. Характеристики

В фиде характеристики записаны на оффере, в `param`. У карточки своего блока свойств нет. Одинаковое значение поднимается на карточку. Разные значения становятся перечнем.

На карточке как одно значение: тип продукта, вендор, отечественное, SaaS.

На карточке как перечень значений офферов: тип поставки (электронная, физическая), способ доставки, пользователь (физлицо, юрлицо), тип организации, тип лицензии (полная версия, подписка, обновление, продление, техподдержка), срок действия, тип и срок техподдержки, размер организации, число пользователей, число узлов, язык интерфейса.

`Назначение` в один перечень не сливается: в параметре одновременно встречаются «для дома» и «сервер».

В перечень не попадают «другое или отсутствует» и «не определено». Перечень не задаёт комбинацию: электронная поставка и юрлицо не означают, что есть электронная лицензия для юрлица. Сочетание проверяется по офферам уже выбранных карточек.

Цена карточки — минимум и максимум среди цен больше нуля. Наличие — число офферов с `available="true"`. Партия остаётся на оффере, поле `sales_notes`.

У электроники лицензионных перечней обычно нет. Имеет смысл хранить заполненные свойства устройства: тип устройства, форм-фактор, семейство процессоров, сокет, интерфейсы, цвет.

## 8. База

SQLite. YML читается один раз при загрузке. HTML страницы товара базой не является.

**classes.** Идентификатор, имя, синонимы запроса, соседние классы.

**cards.** Около 12 500 строк, поисковый индекс. Поля: `id`, `name`, `vendor`, `class_id`, `domestic`, `saas`, `available_count`, `price_min`, `price_max`, перечни характеристик. Поиск по имени, вендору, классу и синонимам идёт сюда. Для электроники строка карточки — это и есть товарная позиция, без дочерних офферов.

**offers.** 127 915 лицензий софта и только они: `id`, `card_id`, `name`, `price`, `available`, `url`, `vendor_code`, характеристики лицензии. Индекс по `card_id`. Чтение только `WHERE card_id IN (...)` для уже отобранных карточек, ориентир 10–20 штук. Выборка всех офферов класса не делается.

Офферы внутрь записи карточки не вкладываются. `data/product_cards.jsonl` для поиска не используется: в каждой строке уже лежат все лицензии карточки.

## 9. Загрузка

Один проход YML.

1. Собрать категории. Карточка софта — категория 3-го уровня, на которую ссылается `group_id`. Карточка электроники — оффер без `group_id`.
2. Назначить класс по полке, по словарю из раздела 6. Для полок-остатков класс берётся из имени карточки и вендора.
3. Посчитать флаги, перечни характеристик, цены больше нуля и число доступных офферов.
4. Записать `classes`, `cards` и, для софта, `offers`.

Повторная загрузка пересобирает базу из фида.

## 10. Обработка запроса

1. Нормализация и словарь. Минимум: «антивирь» — информационная безопасность; «офис» — офисное ПО; «винда» — операционная система; «астра линукс» — карточка Astra Linux Special Edition. «мдаемон» из постановки приводится к имени продукта в каталоге.
2. Разбор в четыре поля. Класс, их может быть несколько. Имя или вендор. Флаги карточки. Фильтры оффера — только то, что прямо сказано в запросе.
3. Карточки. Имя или вендор ищутся в `cards` сразу, класс уточняет. Если имени нет, выборка по классу. Неоднозначный класс запускает и софтовую, и аппаратную ветку из раздела 5.
4. Ранжирование: совпадение имени и вендора, затем `available_count` больше нуля, затем наличие цены больше нуля.
5. Фильтры лицензии для софта проверяются по `offers` только у карточек из короткого списка. Если сочетания нет, карточка остаётся, точная лицензия не отмечается. Для электроники тот же фильтр применяется к самой карточке.
6. Добор соседними классами, пока в ответе меньше четырёх карточек.

## 11. Контракт ответа

Список карточек, не меньше четырёх, если в каталоге есть соседи. У карточки: `id`, имя, вендор, класс, цена от и до, число доступных офферов. У софта при совпавшем фильтре — подходящие офферы: `id`, цена, наличие, `url`. Соседние карточки помечены как дополнительные. Электроника в ответе — одна запись на позицию, без вложенных офферов.

## 12. Приёмка

- «Astra Linux Special Edition» и «астра линукс» возвращают `group:121231`, не полку `222320` и не список из 803 лицензий.
- Windows 11 и Linux попадают в один класс «операционная система» и остаются разными карточками.
- «Антивирь» возвращает карточки класса «информационная безопасность».
- «Сервер» содержит карточки класса «серверы» и программные карточки с серверным назначением. Полка «Серверное ПО» целиком в ответ не входит.
- Запрос с поставкой или типом пользователя не отбрасывает софтовую карточку, если такой лицензии нет.
- Ответ содержит не меньше четырёх карточек за счёт соседних классов.
- Запрос не читает таблицу `offers` без ограничения по `card_id` отобранных карточек.
- Электронная карточка не получает `group_id` и не ищется как набор лицензий.

Десять адресов из выборки запросов — проверка первого результата. Где целевой адрес является карточкой товара, первая карточка ответа соответствует этому товару по имени. Где целевой адрес является полкой или разделом («кибер бэкап», «мтс»), первые карточки относятся к этой линейке, а не к случайному однофамильцу.

## 13. Вне объёма

Подсказки во время ввода, сравнение цен с конкурентами и акции. Текст со страницы вендора можно добавить отдельно. Размещение на витрине и отдельный сервер БД не требуются.
