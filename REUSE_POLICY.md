# REUSE_POLICY.md — переиспользование kultura1905

## Обязательные условия
`kultura1905` — потенциальный донор, не базовая архитектура хакатона. До получения ТЗ код не переносить. После получения ТЗ проверить правила хакатона о ранее написанном коде, лицензии, права на результаты разработки и сторонние зависимости. Если допустимость неясна, не копировать код до решения пользователя. Даже использование отдельных фрагментов требует проверки условий.

Работать с донором только на чтение. Не изменять его исходники, конфиги, Git-состояние и production. Не запускать команды, обращающиеся к production или реальным данным. Не копировать секреты, реальные каталоги, пользовательские логи, ключи, production-конфиги и клиентские данные. Использовать только разрешённые mock-данные хакатона. Путь к донору задаёт пользователь; если он недоступен в sandbox, сообщить об этом, не расширять разрешения самостоятельно.

## Процедура
1. Получить конкретный идентификатор требования из утверждённого ТЗ.
2. По `REFERENCE_PROJECT.md` найти вероятные файлы и адресно прочитать код, тесты и необходимые зависимости. Не сканировать весь донор без причины.
3. Сравнить с простым новым решением по соответствию требованиям, времени адаптации и тестирования, качеству, зависимостям, риску и стоимости runtime. Учитывать, что домен донора — товары для дома, а хакатон — B2B ПО.
4. Представить оркестратору рекомендацию с доказательствами и ограничениями. Не переносить код без решения оркестратора и подтверждённой допустимости.
5. При разрешённом переносе записать источник (репозиторий, ветка/commit, путь), характер адаптации, права/лицензии, зависимости и проверки в журнал решений. Проверить на mock-данных и исключить неявные внешние вызовы.

## Классификация
| Статус | Значение |
|---|---|
| REUSE | Почти без изменений, допустимость и зависимости подтверждены |
| ADAPT | Перенос с предметной или технической адаптацией |
| EXTRACT | Выделение отдельного полезного механизма |
| REFERENCE | Только пример/идея, без копирования реализации |
| REJECT | Не подходит, запрещено либо адаптация дороже новой реализации |

## Формат отчёта Reference Analyst
```text
Требование ТЗ:
Кандидат: путь / символ / commit (если доступен)
Подтверждённое поведение и тесты:
Ограничения, зависимости, права и лицензии:
Различия доменов и mock-данных:
Вариант с нуля:
Оценка времени/риска переноса относительно нового решения:
Рекомендация: REUSE | ADAPT | EXTRACT | REFERENCE | REJECT
Необходимые проверки / решение оркестратора:
```
Если известен только обзор, указать «кандидат, исходный код не проверен». Не выдавать наличие функционала за доказательство качества на новых данных.
