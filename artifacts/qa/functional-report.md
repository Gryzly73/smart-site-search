## События и аналитика F08/F09

После исправления формата UI-полезной нагрузки отдельный TestClient-прогон отправил показ, повтор того же event_id, три клика по одному офферу, две отрицательные оценки на двух запросах, один mock-заказ и несколько неверных событий. Повтор event_id вернул 202 с одной записью в трассе, клики с неправильным offer ID или позицией вернули 422. Форма click/feedback с вложенным request_id первоначально не соответствовала серверной схеме. После исправления обе формы возвращают 202. Аналитика в `functional-events.json` произведена синтетическими тестовыми действиями.

| Показатель | Разрез API real | Разрез API mock |
|---|---:|---:|
| Пустая выдача / завершённые ответы | 1/2 | null, 0/0 |
| Full / определённый исход основной потребности | 1/1 | null, 0/0 |
| Undetermined / принятые запросы | 1/2 | null, 0/0 |
| Ответы с показом / завершённые ответы в воронке | 1/2 | 1/1 |
| Кликнутые / показанные уникальные пары запрос–карточка | 1/1 | 1/1 |
| Отрицательные оценки / запросы с оценкой | 2/2 | null, 0/0 |
| Сессии с заказом / сессии с показом | unavailable | mock, 1/1 |

Синтетический заказ помечается сервером `behavior_mock=true`. Его воронка повторно использует показ и клик исходного запроса из real, поэтому real и mock воронки нельзя складывать. Публичный API отклоняет автоматический клик с `behavior_mock` внутри payload. Синтетический трафик прогона следует держать в отдельной SQLite, чтобы его клики не попадали в реальные показатели стенда. По сессиям нет подтверждённых завершений и доверенных заказов, поэтому уход после поиска, потери и реальная конверсия имеют `unavailable`.

Трассы сохраняют ID выбранного оффера, условия, retrieval, ранжирование, связи при подборе, контекст и попытки провайдера. Частоты в аналитике относятся к ролям, классам или режимам. Исходные строки запросов скрыты, нормализованная строка в журнале null. Выделение пробелов атрибутов и каталога ограничено кодами поисковых проблем. Офферные причины в трассе дают больше детализации, чем текущая агрегированная витрина. Отчёт не содержит реальных KPI продаж.

Токены reasoning равны 0 в исходных вызовах. Инструменты не применялись. План 3 попытки, из них 1 invalid_output, 6 303 входящих и 1 161 исходящий токен. Все 33 имеют usage. Суммарно 65,6016 ₽ с НДС / 53,771803 ₽ без НДС. Это расход выбранного QA-набора с ошибками модели. Повторные попытки, локальный cache hit и пропуски usage в этих реальных измерениях не наблюдались. Провайдерский cached input отличен от локального cache hit. Сверка проводилась по usage API, детализация биллинга не загружалась.

Функциональный и экспертный примеры описывают стоимость успешных маршрутов. Для доставки всех запросов по одному усреднённому значению нужен внешний вес режимов. Затраты внешних API на офлайн-подготовку по manifest равны 0. Серверные затраты на стенд и расходы на разработку не измерялись. Конвертация CBR для этих измерений не требуется, единственная валюта затрат Yandex — RUB.

## Воспроизведение

В PowerShell из корня `smart-site-search`:

```powershell
$env:PYTHONPATH = 'src;.venv'
$env:PYTHONDONTWRITEBYTECODE = '1'
../.venv/Scripts/python.exe -X utf8 -m pytest -p no:cacheprovider tests/acceptance -q
../.venv/Scripts/python.exe -X utf8 tests/acceptance/functional_probe.py --output artifacts/qa/functional-offline.json
$env:SSS_LLM_PROVIDER = 'yandex'
$env:SSS_ENABLE_EXTERNAL_LLM = '1'
$env:YANDEX_GPT_MODEL = 'yandexgpt-5.1'
$env:LLM_TIMEOUT_SECONDS = '18'
$env:LLM_MAX_CALLS_PER_REQUEST = '2'
../.venv/Scripts/python.exe -X utf8 tests/acceptance/functional_probe.py --live --scenario A01a --scenario A04 --scenario A12b --scenario A12c --output artifacts/qa/functional-live-reproduction.json
../.venv/Scripts/python.exe -X utf8 tests/acceptance/test_functional.py
```

Шесть тестов прошли без внешнего провайдера. Live-команда использует локальный `.env` и совершает платные обращения. Сырые ответы провайдера и ключи в файлах отсутствуют. Действия в QA-артефактах синтетические.
